# Search: yes. AI training: no. Same policy as the other daddiego.com.ar sites.
#
# Until this file existed, /robots.txt fell through to the Pages SPA fallback and
# answered 200 with index.html, so crawlers were parsing HTML as robots rules.
#
# This file is the ONLY source of the robots.txt this site serves. Cloudflare's
# zone-level "managed robots.txt" (Security > Settings > Bot traffic) was found
# ON while this was written and Lucas turned it OFF on 2026-09-02; while it was
# on it PREPENDED its own "User-agent: *" block, so the served file had two of
# them. If a duplicate group with Cloudflare's wording ever reappears above this
# one, it got switched back on: fix it in the dashboard, not in the repo.

User-agent: *
Content-Signal: search=yes,ai-train=no,use=reference
Allow: /

# Nothing is disallowed on purpose: the page renders client-side from the data
# artifact (/assets/series.v1-<hash>.json), so a crawler that cannot fetch that
# file sees an empty shell.
# Blocking the data artifact would cost the search listing, not protect it.

# No AI model training. The AI *search* bots (OAI-SearchBot, Claude-SearchBot,
# PerplexityBot) are left out on purpose: being cited there is fine.

User-agent: Amazonbot
User-agent: Applebot-Extended
